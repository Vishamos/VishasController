# 최소 실행 테스트

에러 없이 빌드되는지만 본다. 명세 기준 검증은 qa가 한다(`qa-test`).

## 허용된 명령
아래 명령만 승인 없이 실행된다. 다른 명령을 `&&`·`;`로 붙이면 승인 요청이 뜨므로 **한 줄에 하나씩** 실행한다.
- `dotnet build VishasController.sln`
- `dotnet test VishasController.sln` (테스트 프로젝트가 생긴 뒤)

## 순서
1. **빌드**: `dotnet build VishasController.sln`
   - 통과 기준: 오류 0개, **새 경고 0개**. 지금 기준은 경고 0개다. 경고가 생기면 고치거나 이유를 보고한다.
   - `MSB3027`·`MSB3021`(파일이 사용 중이라 복사 실패)이면 트레이 앱이나 TestServer가 실행 중이라서다. 실패로 보지 말고 "앱을 종료한 뒤 다시 빌드 필요"로 보고한다. 프로세스를 직접 끄지 않는다.
2. **단위 테스트**: 테스트 프로젝트가 있으면 `dotnet test VishasController.sln`. 없으면 "테스트 프로젝트 없음"으로 생략한다.
3. **화면 확인은 하지 않는다.** 트레이 앱(WinForms)과 TestServer(콘솔 명령 입력)는 이 환경에서 실행해 확인할 수 없다. 실행하지 않는다.
   - 대신 보고에 "사용자가 확인할 것"을 적는다: TestServer 실행 명령(`dotnet run --project tools/TestServer`, 필요하면 `-- --no41`), 입력할 콘솔 명령 순서(`m`, `d`, `kick` 등), 기대하는 트레이 아이콘 색·알림·채팅 창 동작.

## 임시 파일
- 확인용 코드가 꼭 필요하면 `.temp/`(git 제외)에 Write 도구로 만들고, 실행 전에 "규칙 예외 제안"으로 실행 명령을 알린다(허용 목록에 없음). 끝나면 지운다.

## 결과
- 단계마다 통과/실패/생략과 이유.
- 화면으로만 확인할 수 있는 것은 "사용자가 확인할 것"으로 넘긴다.
